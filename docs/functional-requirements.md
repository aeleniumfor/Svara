# 機能要件仕様書

## 0. 目的 / スコープ

- 本システムは「Backlog中心のタスク整理」を最優先とし、日々の運用でタスクを **期限駆動（due_at）** で管理できることを目的とする。
- 最優先は「Backlog画面」。次点で「期限なし専用画面」を提供する。
- 手動での並び替え（任意順）は提供しない。並びは常に自動ソートとする。

---

## 1. データモデル（機能観点）

### 1.1 TaskStatus

TaskStatus は以下の4種とする。

| 値 | 説明 |
|---|---|
| `backlog` | バックログ |
| `doing` | 着手中 |
| `waiting` | 外部待ち / ブロック |
| `done` | 完了 |

### 1.2 日時フィールド

| フィールド | 説明 | null 許容 | 備考 |
|---|---|---|---|
| `due_at` | 期限 | ○ | 制約は 6章を参照 |
| `done_at` | 完了日時 | 条件付き | `status == done` のときのみ値を持つ。`status != done` のときは常に null |

### 1.3 タグ

- タグはタスクの分類に利用する（閲覧・フィルタ用途）。
- タグは作成/削除できる（CRUD のうち更新は非必須）。
- タグ名は正規化して `key` を生成する（例：前後空白除去 + 小文字化）。
- `Tag.key` は一意とする（同一キーの重複作成は禁止）。

## 2. 画面一覧

| # | 画面名 | 優先度 | 概要 |
|---|---|---|---|
| 1 | Backlog画面 | 最優先 | 期限ありタスクの管理画面 |
| 2 | 期限なし専用画面 | 次点 | 棚卸し・整理用 |

---

## 3. Backlog画面（最優先）

### 3.1 画面構成

- 1画面内に **3セクション** を固定表示する。
  - セクション順：`backlog → doing → waiting`
- 各セクションの一覧はスクロール可能とする。

### 3.2 表示対象

- **期限あり（`due_at != null`）のタスクのみ** 表示する。
- 期限なし（`due_at == null`）は Backlog画面には表示しない（期限なし専用画面に集約）。

### 3.3 一覧の表示項目

| 区分 | 項目 |
|---|---|
| 必須表示 | `title` |
| 任意表示（推奨） | 期限切れ強調のラベル / アイコン（8章）、タグ（表示のみ） |

### 3.4 セクション内の並び順

セクション内の並び順は以下のキーで決定する（優先度順）。

| 優先度 | キー | 方向 |
|---|---|---|
| 1 | `due_at` | 昇順（近い順） |
| 2 | `updated_at` | 降順（新しい順） |
| 3 | `id` | 昇順 |

- `due_at` の変更により、一覧内の位置は **即時に再計算** される（自動で並び替わる）。

### 3.5 詳細パネル（右側 / モーダル）

- 一覧のタスクをクリックすると、**一覧を残したまま** 詳細パネルを開く。
- 詳細パネルの仕様：
  - 閲覧と編集を **同一パネル** で行える。
  - 編集可能フィールド：`title` / `due_at` / `note`
  - `status` は詳細パネルでは編集しない（ステータス操作は 5章に集約）。

### 3.6 Note（注力機能）

| 要件 | 詳細 |
|---|---|
| 入力領域 | 長文を書きやすいUI（十分な入力領域） |
| 入力形式 | Markdown入力対応 |
| 表示モード | 「編集 / プレビュー」の切り替え式（同時表示しない） |

### 3.7 保存仕様

- 編集内容は **自動保存** とする。
  - トリガ：入力停止（例：数秒）またはフォーカスアウト
  - 保存失敗時はエラーを表示し、再試行可能とする。

## 4. タグフィルタ（Backlog画面）

| 項目 | 仕様 |
|---|---|
| 選択方式 | 複数選択可能 |
| 条件 | OR（いずれかのタグに一致したタスクを表示） |
| 適用範囲 | `backlog` / `doing` / `waiting` の全セクション |
| フィルタ状態の保持 | 画面内で保持する（リロードでの保持は非要件） |

---

## 5. ステータス変更（Backlog画面：一覧操作）

### 5.1 操作範囲

- Backlog画面の一覧側での即時操作は **ステータス変更のみ** とする。

### 5.2 操作手段

- ステータス変更は **ドラッグ＆ドロップ** により行う。
  - セクション間移動のみを対象とする。
  - 同一セクション内の手動並び替えは提供しない（並びは 3.4 に従う）。

---

## 6. due_at 制約（期限運用）

### 6.1 ステータス別の due_at 制約

| ステータス | `due_at` | 備考 |
|---|---|---|
| `backlog` | 任意（null 許容） | — |
| `doing` | **必須**（null 禁止） | — |
| `waiting` | **必須**（null 禁止） | — |
| `done` | 任意（制約なし） | — |

### 6.2 ブロック動作（Backlog画面）

`due_at == null` のタスクを `doing` / `waiting` に移動しようとした場合：

1. **移動をキャンセル** する。
2. 「期限が必要である」ことを **通知** する（トースト等）。
3. 期限設定への **導線（CTA）** を提示する。
   - CTA押下 → 詳細パネルを開き、`due_at` 入力欄にフォーカスする。
   - その場で期限入力UIを新規に出さない。

---

## 7. 期限なし専用画面（棚卸し・整理）

### 7.1 目的

- 期限なしタスクを集約し、期限設定と整理を高速に行う。

### 7.2 表示対象

- `due_at == null` のタスクのみを表示する。
- 主な対象は `backlog` の期限なし（`doing` / `waiting` は 6章により原則発生しない）。

### 7.3 可能操作

一覧で素早く行える操作として、以下を提供する。

| 操作 | 必須 / 推奨 | 備考 |
|---|---|---|
| `due_at` の設定 | 必須 | — |
| `status` の変更 | 推奨 | 6章の制約を適用 |

**status変更の制約：**

- `due_at` が null のまま `doing` / `waiting` へは遷移できない。
- `doing` / `waiting` に変更する場合は、先に `due_at` を設定してから変更可能とする。

---

## 8. 期限超過の見せ方（強調表示）

### 8.1 判定条件

```
due_at < 現在時刻  AND  status != done
```

### 8.2 表示仕様

- 期限切れタスクは一覧で **強調表示** する（ラベル / アイコン等）。
- `status == done` のタスクは期限切れ強調 **対象外** とする。

---

## 9. done_at の自動制御

| トリガ | 動作 |
|---|---|
| `status` が `done` になった瞬間 | `done_at` に現在時刻を自動設定 |
| `status` が `done` 以外になった瞬間 | `done_at` を null に自動設定 |

- 上記はユーザー操作に依存せず、常に整合性を保つ。

---

## 10. 非機能（最低限の明文化）

| 項目 | 仕様 |
|---|---|
| タイムゾーン | `Asia/Tokyo` |
| `due_at` の精度 | **日付のみ**（時刻入力は扱わない）。API上は ISO8601 datetime 文字列だが、意味論としては JST の 00:00 固定（例：`2026-02-14T00:00:00+09:00` または同等のUTC表現）。 |
